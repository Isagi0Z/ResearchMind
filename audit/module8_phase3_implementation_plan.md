# Module 8 Phase 3 Implementation Plan: Frontend ↔ FastAPI Integration

## 1. Architecture Summary
The transition from M7 mock services to the M8 FastAPI backend is partially ready.
- **Ready Subsystems:** `Query` and `Review` engines have functioning API routes. The underlying M5 and M6 engines are deterministically safe and tightly integrated via Pydantic.
- **Unready Subsystems:** `Dashboard`, `Corpus`, `Graph`, and `Monitoring` endpoints currently raise HTTP 501 Not Implemented.

## 3. Gap Analysis
The critical gap is the divergence between the monolithic object generated by the frontend mocks and the structured, step-by-step Pydantic models expected by the backend. Specifically for Query, the frontend must orchestrate calls to `/parse`, `/plan`, `/route`, and `/answer`, whereas the mock currently generates the final object in one synchronous sweep.

## 4. Risk Assessment Summary
- **Critical Risk:** Prematurely wiring unready endpoints (Dashboard, Corpus, Graph, Monitoring) will break the application.
- **High Risk:** Schema validation failures due to missing nested fields (e.g., `ReviewRequest` structure mismatches).
- **Medium Risk:** UI UX degredation from synchronous mock resolution to asynchronous network states.

## 5. Go / No-Go Recommendation
**Recommendation: PARTIAL GO (Conditional)**

Implementation may proceed **ONLY** for the **Query** and **Review** interfaces.
The Dashboard, Corpus, Graph, and Monitoring views **MUST** continue using their respective mock implementations until the backend functionality for those endpoints is constructed. All code changes must be strictly bounded to `D:\RM\frontend\services` modifications and must not spawn any external worktrees.
